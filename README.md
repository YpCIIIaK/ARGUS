# ForumDS

Один Discord-бот, внутри которого работают пять ИИ-агентов: Программист, Инженер, Креативщик, Исследователь и Координатор. Ответы создаются через OpenRouter, а история сохраняется в PostgreSQL.

## Что уже работает

- обычное сообщение выбирает до двух подходящих агентов;
- `!discuss <тема>` запускает раунд со всей командой;
- агенты видят предыдущие сообщения текущего канала;
- ответы публикуются с разными именами через Discord webhooks;
- при отсутствии права `Manage Webhooks` ответы отправляются embeds от имени бота;
- `!agents`, `!status`, `!pause`, `!resume` управляют системой;
- `!bounty` показывает последнее сообщение из изолированного канала Bounty Monitor, `!bounty <вопрос>` передаёт его историю агентам, `!bounty status` проверяет состояние, а `!bounty scan` запускает скан;
- персональные каналы `#developer`, `#engineer`, `#creative`, `#researcher`, `#coordinator` автоматически направляют свободный текст одному агенту и хранят отдельный контекст;
- `!context`, `!model`, `!compact` и `!clear` показывают состояние и управляют памятью персонального канала;
- `!settings` в канале `#настройки-⚙` открывает кнопочную панель для моделей, контекста, использования и общих лимитов;
- `/health` подходит для проверки Render и внешнего cron;
- длинные ответы автоматически разбиваются под лимит Discord, временные ошибки OpenRouter повторяются до трёх раз;
- `!stop` немедленно останавливает активную генерацию в текущем канале;
- обработанные Discord-события дедуплицируются в PostgreSQL, а `/health` проверяет Discord и базу;
- дневной лимит запросов хранится в PostgreSQL и не обнуляется при редеплое Render;
- агенты знают возможности команды и могут передавать конкретные подзадачи друг другу;
- цепочка делегирования показывается в обновляемом сообщении прогресса и защищена от циклов;
- обращения и ответы между агентами публикуются в канале как видимый рабочий диалог;
- Программист умеет создавать до трёх текстовых файлов за вызов и прикладывать их к сообщению Discord;
- PostgreSQL хранит историю и состояние паузы; без `DATABASE_URL` используется временная память.

## Локальный запуск

1. Создайте приложение и бота в [Discord Developer Portal](https://discord.com/developers/applications).
2. Включите **Message Content Intent** на странице Bot.
3. Добавьте бота на сервер с правами View Channels, Send Messages, Read Message History и Manage Webhooks.
4. Скопируйте `.env.example` в `.env` и заполните `DISCORD_TOKEN` и `OPENROUTER_API_KEY`.
5. Выполните:

```powershell
npm install
npm run dev
```

## Развёртывание на Render

1. Загрузите проект в Git-репозиторий.
2. В Render выберите **New Blueprint** и подключите репозиторий: настройки возьмутся из `render.yaml`.
3. Заполните секреты `DISCORD_TOKEN`, `OPENROUTER_API_KEY` и `DATABASE_URL`.
4. Направьте внешний cron на `https://<service>.onrender.com/health` с интервалом меньше 15 минут.

`AUTONOMOUS_ENABLED` пока оставлен выключенным: первый этап реагирует на людей и команду `!discuss`. Самостоятельный планировщик добавляется после проверки основного цикла в реальном Discord.

## Переменные окружения

Полный список находится в `.env.example`. Через `ALLOWED_CHANNEL_IDS` можно ограничить каналы, через `OWNER_IDS` — пользователей с правом паузы, а через переменные `*_MODEL` назначить каждому агенту отдельную модель OpenRouter.

Для интеграции Bounty Monitor задайте `BOUNTY_CHANNEL_ID`. В самом bounty-канале агенты не отвечают автоматически; бот только читает его историю по команде из другого канала.

Для команд управления также задайте `BOUNTY_MONITOR_URL` адресом проекта Vercel и `BOUNTY_MONITOR_TOKEN` тем же значением, что `MANUAL_TOKEN` в проекте Bounty Monitor.

## Персональные каналы агентов

Имена каналов определяются автоматически. При необходимости их можно привязать строго по ID через `PROGRAMMER_CHANNEL_ID`, `ENGINEER_CHANNEL_ID`, `CREATIVE_CHANNEL_ID`, `RESEARCHER_CHANNEL_ID`, `COORDINATOR_CHANNEL_ID`.

- `!status`, `!context` или `!session` — модель, начало сессии, размер контекста, запросы, токены и стоимость;
- `!model` — текущая модель агента;
- `!compact` — заменить длинную историю рабочей сводкой;
- `!clear` — очистить память канала и начать новую сессию, не удаляя сообщения Discord;
- `!help` — список команд.

## Панель настроек

В канале `#настройки-⚙` обычный текст игнорируется. Команда `!settings` публикует панель Discord Components. В ней можно:

- выбрать одного из пяти агентов;
- заменить его модель OpenRouter;
- настроить число сообщений контекста;
- сжать или очистить его память;
- посмотреть суммарные токены и стоимость каждого канала;
- изменить максимум ответов за раунд, дневной лимит запросов и максимум токенов ответа.

Дневной лимит общий для всего Discord-сервера. Один вызов одного агента или компактизация контекста расходует одну единицу; автоматические повторы того же запроса при временной ошибке OpenRouter дополнительных единиц не расходуют. Счётчик сбрасывается в 00:00 UTC. Максимум токенов применяется отдельно к каждому ответу агента, а лимит ответов за раунд ограничивает число вызываемых агентов для одного сообщения.

## Совместная работа агентов

Если выбранному агенту не хватает возможности, он может передать подзадачу подходящему участнику. Например, Исследователь собирает материал и просит Программиста создать `report.md`. ARGUS допускает не более пяти внутренних передач за запуск, глубину не более трёх уровней, запрещает вызов самого себя и повтор одинаковой подзадачи. Каждый вызов помощника учитывается в дневном лимите OpenRouter.

Передача отображается сообщением исходного агента с визуальной отметкой `@Имя`, ответ помощника адресуется обратно, а исходный агент после получения результатов делает итоговый ответ пользователю. Финальный итог после делегирования требует ещё одного запроса к модели и тоже учитывается в дневном лимите. Имена агентов реализованы Discord-вебхуками, поэтому отметка показывает адресата диалога, но не создаёт настоящее системное упоминание пользователя Discord.

Первый доступный инструмент — создание текстового файла Программистом. Имя очищается от путей и опасных символов, размер ограничен 1 МБ, а содержимое отправляется напрямую как вложение Discord без сохранения на временном диске Render.

## Подключение GitHub

ARGUS использует GitHub App и запоминает отдельную привязку для каждого Discord user ID. Пользователь выбирает один рабочий репозиторий, после чего Программист может читать текстовые файлы и предлагать создание, полную замену или удаление файлов.

1. В GitHub откройте **Settings → Developer settings → GitHub Apps → New GitHub App**.
2. Укажите Homepage URL вашего Render-сервиса и точный Callback URL `https://<service>.onrender.com/auth/github/callback`. Не включайте wildcard matching.
3. В Repository permissions оставьте `Metadata: Read-only` и задайте `Contents: Read and write`. Остальные разрешения не требуются. После повышения прав существующую установку нужно отдельно подтвердить на странице Installed GitHub Apps.
4. Включите истекающие user-to-server tokens. ARGUS обновляет их с помощью refresh token.
5. Разрешите установку на нужный аккаунт, выберите только необходимые репозитории и скопируйте `Client ID`, новый `Client secret` и slug приложения из URL `github.com/apps/<slug>`.
6. Сгенерируйте отдельный ключ шифрования:

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

7. Добавьте в Render Environment переменные `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `GITHUB_APP_SLUG`, `GITHUB_CALLBACK_URL` и `GITHUB_TOKEN_ENCRYPTION_KEY`.

Команды пользователя:

- `!github` или `!github connect` — кнопочная панель; персональная ссылка авторизации действует 10 минут;
- `!github` — текущая привязка;
- `!github repos` — репозитории, выбранные при установке GitHub App, и выбор одного рабочего репозитория;
- `!github disconnect` — подтверждаемая отвязка, удаление локальных токенов и отзыв GitHub authorization grant.

Access и refresh tokens хранятся в PostgreSQL в формате AES-256-GCM. OAuth `state` сохраняется только как SHA-256 hash, одноразово потребляется callback-обработчиком и привязывает GitHub-аккаунт к инициировавшему команду Discord-пользователю. Удаление authorization grant не удаляет саму установку GitHub App из репозиториев; её можно отдельно удалить или изменить в настройках **GitHub Apps → Installed GitHub Apps**.

Статус подключения, названия приватных репозиториев, OAuth-ссылка и результат отвязки никогда не публикуются для всего канала. Команда показывает безопасную кнопочную панель, а результат нажатия Discord отображает как ephemeral-ответ только владельцу панели.

Программист читает не более пяти файлов за один шаг: до 200 КБ на файл и до 500 КБ суммарно. Путь не может выходить за репозиторий; `.env`, приватные ключи, `.git` и бинарные файлы блокируются. Один пакет содержит до десяти уникальных файлов и не более 5 МБ нового содержимого. Полный пакет доступен владельцу как приватное вложение по кнопке **Просмотреть** и действует 15 минут.

Кнопка **Применить в новой ветке** повторно проверяет доступ к репозиторию, создаёт ветку `argus/<дата>-<id>` от текущей основной ветки и выполняет изменения там. Основная ветка напрямую не изменяется. Исключение — полностью пустой репозиторий: у него ещё нет commit SHA, поэтому отдельную ветку создать невозможно; после явного предупреждения кнопка создаёт первый коммит и основную ветку. Кнопка **Отменить** удаляет ожидающий пакет.

Кнопки и формы доступны владельцам и администраторам сервера. Значения сохраняются в PostgreSQL в таблице `runtime_settings`.
